# Template browser tests

Each template's browser tests live in its own package, `templates/<id>/test/browser.test.ts` (the look kit's in `packages/template-looks/test/looks.test.ts`), and run as that package's `test` task: `pnpm --filter @signforge/template-<id> test`. A change to one template reruns only its own tests on a pull request (docs/ci.md). This package is the harness they share.

Chromium, not the Pi: these tests check behaviour, not frame rates. Performance still needs a Pi measurement (`device/pi/isolate.py`). If Playwright's Chromium is missing: `pnpm --filter @signforge/player exec playwright install chromium`.

## The harness

- `useTemplate(new URL('..', import.meta.url), update)` starts every test file. It launches one headless Chromium for the file, builds the template as `sf build` does (`@signforge/template-build`), closes each test's pages after it, and registers the update lifecycle check: `update.b` sent after `update.a`, with a `reset` between (the editor's path) and without one, must leave exactly the document a fresh load of `b` gives. `assetsA` and `assetsB` name the colour each image field is drawn in (see `Host.init`); `full` hosts the frames at 1920x1080. It returns the built template.
- `host(orientation, full)` is a page of sandboxed frames that speaks the frame protocol as the player does, each frame 960x540 (or 1920x1080 with `full`). `open`, `init` (data, drawn images with or without their samples, the clock, a brand kit, the duration, the zone, a logo), `post`, `waitFor` and `dom`. Time comes from `init`'s clock, `NOW` unless a test says otherwise: a Tuesday afternoon in UTC.
- `screenFrame(t, orientation, assets)`: one frame at a screen's own size, with `play(data, theme)`.
- `spotData(manifest, over)`: the template's defaults with `over` on top, as the compiler hands a spot to the player.
- `DEMO_KIT`, `LIGHT_KIT` and `noDemoAndLight(light)`: the kits a template's painted contrast is measured under.
- `paintedContrast(page, frame, scope)`: each text in `scope` that reads below AA (4.5:1, 3:1 large), measured from screenshots with and without the text, so opacity and anything drawn over it count.
- `brandColourTests(t, { spots, onFill, onBackdrop, sameWithSample })`: text on a brand colour (#57, #69, #92), in landscape and portrait, under no kit, the demo kit, a kit whose on-colours fail, a light kit, a borderline accent, mid-tone accents (green on white, blue on dark), an accent just over 3:1 on its background and a mid-tone background. Text on a fill reads at its ratio; accent-coloured text reads on whatever is behind it, measured from a screenshot with the text hidden (4.5:1, 3:1 for text that is large at 1080p), in the kit's accent wherever that reads.
- `layoutFaults(frame, also, crosses, inside)`: text past the screen, past its clamp or out of a box that clips it, painted over, or overlapping another text.
- `motion(frame, durationMs, every)`: the properties a play animates, whether at most 50 elements animate, and the kit-animated elements with no outro ending with the spot, and each element naming keyframes that do not exist (`unknown`), which would show it from the first frame.
- `motionContract(frame, durationMs, loops)`: where a play breaks D's motion (docs/template-spec.md, Motion). Each animation, CSS, transition or script, is seeked alone against its element at rest. It names an entrance off the decelerating curve, outside 400 to 650 ms or past 1.5vmin; an exit off the accelerating curve, not 300 ms, not ending with the spot, past 0.6vmin or reversed; a mid-play move off the standard curve or off the screen; a rotation, an overshoot through any number of keyframes, a scale past 0.94 to 1.04, a clip-path or mask animation, or a loop outside `loops`.
- `INTRO_WINDOW_MS`: every entrance starts and ends inside it; `layoutFaults` reads rest from the entrances in it.

## Adding a template

A new template gets `test/browser.test.ts` and `test/tsconfig.json` (copy another template's), a `test` script (`vitest run`), and `@signforge/template-test`, `vitest` and `@types/node` as devDependencies. `scripts/check-template-deps.sh` fails until it has them. Start the file with `useTemplate` and two sets of data that differ in every list and toggle the template has.
