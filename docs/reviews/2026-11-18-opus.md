# Full review, 2026-11-18 (origin/master @ 5c08bb8), Opus

Reviewed read-only from a throwaway worktree. Open PRs #14, #18, #19 and #20 were not reviewed.

## Verdict

The tenancy boundary still holds. I found no way across orgs. Every route takes its org from a session, a credential or a claim, never from the request (`scoped()`, `findDeviceScreen`, `requireOrg`, the ticket check against live credentials). Most of the 2026-11-17 review was fixed with code and browser tests, not just with notes:

- template containment;
- last known good;
- pinning;
- runtime schemas in the contract;
- audit and write batching;
- idempotency keys;
- the pixel cap.

What remains is less about the boundaries and more about the gaps between finished parts:

- **The one real publish path is still `/admin`.** It runs on a single deploy-wide secret, so the draft model is real only in tests.
- **Screen versions move when they should not.** A screen reporting a manifest moves the row version the CMS uses for conflicts, so a plain publish can make an editor's save fail.
- **The README's performance table is out of date.** It quotes an older build than the one that ships, and that build now breaks two budgets.
- **Nothing outside the page watches the player.** Unattended screens have no recovery if the player hangs.

None of these is an emergency. The first two should land before the editors (M3-16 to M3-18).

## What I checked and found sound

- **Device auth.** Every live credential is compared in constant time, and the same 401 comes back for every failure (`device/auth.ts`).
- **Socket tickets.** They are HMAC-signed with domain separation and re-checked against live credentials (`ticket.ts`, `socket.ts:20-21`).
- **Pairing.** Claims are rate limited per member and per address, an unknown code and another org's code get the same answer, and collect is a guarded batch (`db/src/pairing.ts`, `scoped.ts` `pairing.collect`).
- **Blob headers.** Responses are `nosniff`, sandboxed by CSP, and markup is sent as `attachment` (`r2.ts`).
- **CSRF.** The JSON-only tool route needs a preflight that the API never grants.
- **The supervisor.** It answers only requests that come from the player's origin and Host and carry its token.
- **The preview channel.** It is gated on the parent's origin and window.
- **Feeds.** Feeds that declare a DOCTYPE or entities are refused (`feeds/src/news.ts:29-37`).
- **CMS React rules.** There is no `useEffect` or `useState` in `apps/cms/src`; the CMS uses Zustand slices.

## The three things I would do next

1. **Make publishing real and retire `/admin`'s screen routes (F2, A4, A1 fan-out).** Build M3-16 to M3-18 on `publishOrg`, design per-screen fan-out from the start, then delete the deploy-secret path to any org's screens.
2. **Fix the small correctness items before the editors build on them (F1, F5, F7), and add the liveness watchdog (F4).** Each is a day or less. F1 will show up as spurious conflicts as soon as people use the screen editor during a rollout.
3. **Bring the performance story current and close the open budgets (F3).** That means:
   - update the README from the 2026-11-18 numbers;
   - add the template-process warm-up for the first prepare;
   - finish the news-under-video work (M3-25's open Pi box, M3-45).

   Before any M4 work starts, build the headless-render request check that agent templates depend on.
